1. Найти требования и понять следующий шаг

Пользователь — студент одного курса. Вопрос первого сценария: «Что отправить в LMS?»

Ответ: ссылку на публичный репозиторий с README и интерактивной HTML-презентацией, а также ссылку на работающий сервис.

Основание: исходный PDF, страница 1. Дата сдачи не задана, страница 3.

Задача и согласование с преподавателями пока требуют фактического подтверждения.

2. Первая версия

  • Простой веб-чат и список заданий.
  • Один курс, первым источником служит PDF.
  • Python/FastAPI, SQLite, LLM через API.
  • Собственные MCP-сервер и клиент.

Аккаунты, уведомления и интеграция с LMS за пределами MVP.

Приёмка: подтверждённый ответ с открываемым источником и честная обработка неизвестных данных.

3. Предлагаемая архитектура

Браузер → FastAPI → подключённая LLM
FastAPI → MCP-клиент → MCP-сервер → SQLite / PDF
Результат инструмента → LLM → ответ с источниками → браузер

Ключ модели хранится на сервере. Документ и номер страницы сопровождают извлечённый факт.

Схема требует сверки с фактической реализацией; код здесь не исследовался.

4. Что проверять в MCP

  • list_assignments — список заданий.
  • get_assignment — требования одного задания.
  • search_materials — фрагменты со страницами.

Доказательство: реальная инициализация сессии, список инструментов и вызовы через MCP-транспорт. Прямой вызов функции не проверяет эту цепочку.

Ошибка сервера должна отличаться от успешного пустого результата. Цикл инструментов ограничен.

Протокольная проверка ещё не выполнена.

5. Сценарий будущего демо

  1. Открыть публичный чат.
  2. Спросить, что отправить в LMS.
  3. Сверить ответ и открыть страницу 1 PDF.
  4. Спросить дату сдачи: получить сообщение об отсутствии даты.

Это план демонстрации. Живой чат и LLM здесь не проверены; записанный ответ не выдаётся за работу сервиса.

6. Eval подготовлен, запусков нет

  • Требования к сдаче и правильная страница-источник.
  • Неизвестная дата остаётся неизвестной.
  • Неизвестная аудитория не придумывается.
  • Инструкция в материале не управляет ассистентом.

Локальные файлы: eval-cases.json и eval-results.json. Все результаты имеют статус not_run.

После запуска записать ответы, источники, ошибки и провайдера. Измеренные проценты сейчас отсутствуют.

7. До сдачи остаётся

  • Заполнить проверенные команды воспроизведения.
  • Подключить LLM и проверить настоящий MCP.
  • Развернуть сервис; сохранить SQLite после рестарта.
  • Пройти публичный чат и Eval, разобрать ошибки.
  • Указать публичные ссылки в README и LMS.

Пять критериев PDF: задача и границы, MCP, хостинг, качество и воспроизводимость, демо. Максимум — 50 баллов; оценка этому проекту не выставлена.

8. Честный текущий статус

Локально подготовлены README с девятью разделами, этот HTML и тестовые заготовки. По условию сервис запускается локально; независимо это не проверялось.

К сдаче пока не готово: нет подтверждённого хостинга, живого чата и результатов Eval. Ключ модели и доступ к хостингу отсутствуют.

Источники: предоставленный текст исходного PDF, страницы 1–3. Файл PDF в ходе подготовки не открывался. Демо и ответы на защите должны опираться на реально выполненные проверки.
