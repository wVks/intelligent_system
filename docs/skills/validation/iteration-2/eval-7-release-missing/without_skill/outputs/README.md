## 4. Архитектурная схема

Предлагаемая схема, которую нужно сверить с фактическим кодом:

```text
Браузер → FastAPI → LLM API
              ↓       ↑ результаты инструментов
          MCP-клиент → MCP-сервер → SQLite / страницы PDF
              ↓
       ответ и ссылки → браузер → исходный PDF
```

Ключ API хранится в серверном окружении. PDF и результаты инструментов — данные, не инструкции для изменения поведения ассистента. Источник факта включает документ и номер страницы.

## 5. Схема MCP

Планируемые инструменты:

| Инструмент | Вход | Результат |
|---|---|---|
| `list_assignments` | необязательный фильтр | задания, идентификаторы, сроки и источники |
| `get_assignment` | `assignment_id` | детали задания или явная ошибка идентификатора |
| `search_materials` | текст запроса, лимит | фрагменты с документом и страницей |

Последовательность: backend инициализирует MCP-сессию, получает список инструментов и выполняет запрос модели через MCP-клиент. Прямой вызов Python-функции проверяет обработчик, но не транспорт.

**Не выполнено:** запуск сервера, протокольная инициализация, получение списка инструментов, вызов каждого инструмента, проверка ошибки при отключённом сервере. Для отчёта сохранить обезличенный trace и версию приложения.

## 6. AI-логика

Подключённая LLM получает вопрос и доступные инструменты, вызывает нужный инструмент и формирует ответ по полученным данным. Backend проверяет аргументы, ограничивает число раундов и время запроса. Недоступность инструмента не считается пустым списком заданий.

Дата сдачи неизвестна: `deadline: null`. Для плана без даты ассистент уточняет её и может предложить относительные дни с явно указанными предположениями. Неподтверждённые сведения не выдаются за факты. Инструкция внутри материала не должна заменять правила ассистента.
