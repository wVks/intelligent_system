# StudyNavigator — подготовительные материалы сдачи

> Изолированный учебный шаблон. Указанные схемы — план MVP, не доказательство реализованного приложения. По условию сервис запускается только локально, README уже есть, Eval не проводился. Сам запуск здесь не повторялся. Ключа LLM и доступа к хостингу нет.

## 1. Название проекта и описание задачи

StudyNavigator помогает студенту одного курса найти требования задания и составить выполнимый план подготовки по материалам. Первый сценарий: «Что отправить в LMS?». По странице 1 исходного PDF нужны две ссылки: на публичный репозиторий с README и интерактивной HTML-презентацией и на работающий сервис. Дата сдачи не задана; `due_date` и `due_at` должны оставаться `null`.

## 2. Пользователь и сценарий использования

Пользователь — студент курса. Он задаёт вопрос в веб-чате, получает ответ с поддерживающим фрагментом и открывает соответствующую страницу PDF. При отсутствии сведений система должна сообщить об этом; при ошибке MCP — показать недоступность данных, не утверждать отсутствие заданий. Для планирования нужна дата или явно выбранный горизонт и бюджет времени.

## 3. Границы MVP

Выбраны Python/FastAPI, SQLite, простой HTML/CSS/JavaScript, серверный вызов LLM по API и собственные MCP-сервер/клиент. Доступ к заданиям только для чтения. Реальная LMS, аккаунты и уведомления не входят в MVP.

Критерии готовности: ответ про обе ссылки подтверждён страницей 1; источник открывается; неизвестная дата не выдумана; план укладывается в доступное время; отказ MCP отличим от пустого результата; реальная модель вызывает инструменты через MCP. **TODO:** сопоставить эти критерии с фактическим кодом и приложить доказательства. Согласование задачи с преподавателями не подтверждено.

## 4. Архитектурная схема системы

Предполагаемый поток: веб-чат → FastAPI → LLM → MCP-клиент → MCP-сервер → SQLite/материал PDF → результат инструмента → LLM → проверенный backend ответ → веб-чат.

Backend хранит ключ в окружении, проверяет сроки, часы и связи источников. UI отображает безопасный текст и источники. **TODO:** заменить схему на подтверждённую реализацию; приложить безопасную трассу фактического запроса.

## 5. Схема MCP-интеграции

Планируются читающие `list_assignments(course_id?)`, `get_assignment(assignment_id)` и `search_materials(query, limit)`. Клиент обнаруживает инструменты через протокол, пересекает их с allowlist, валидирует аргументы и передаёт реальные результаты модели с ID вызова.

Источники: `source_id`, `title`, `page/section`, `excerpt`, backend-generated `url`; ссылки — `source_ids`. Пустой поиск, ошибка инструмента и недоступность транспорта различаются. Число шагов и общий timeout ограничены.
