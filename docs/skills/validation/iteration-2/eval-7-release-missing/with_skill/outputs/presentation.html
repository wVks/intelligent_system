Учебный веб-ассистент: требования, задания и выполнимый план.

Подготовительные материалы. Публичный сервис и live LLM не проверены. Eval не проведён.

1. Проблема и пользователь

Студенту одного курса нужно понять, что сдавать, найти подтверждение и распределить подготовку.

Первый сценарий: «Что отправить в LMS?» Ответ по странице 1 PDF: две ссылки — на публичный репозиторий с README и HTML-презентацией и на работающий сервис.

Ориентир: 1 минута. Это план времени, а не измеренный хронометраж.

2. Границы MVP

Веб-чат, список заданий, один курс, SQLite и исходный PDF. Нет реальной LMS, аккаунтов и уведомлений.

Критерии: подтверждённый ответ; открываемый источник; неизвестный срок остаётся null; план укладывается в бюджет; ошибка данных видна пользователю.

3. Архитектура и MCP

Проектируемый поток: браузер → FastAPI → LLM → MCP-клиент → MCP-сервер → SQLite/PDF → ответ с источником.

Три читающих инструмента: list_assignments, get_assignment, search_materials. Ключ модели остаётся в backend.

Результат: требования + source_ids + каталог sources
Источник: PDF, страница 1; due_date: null, due_at: null

4. План демонстрации

  1. Спросить об отправке в LMS и открыть страницу 1 источника.
  2. Спросить о дате защиты: в PDF её нет, ожидается уточнение.
  3. Попросить план на 2 часа при задачах на 5: должен быть показан дефицит 3 часа.

Демо не выполнено: нет ключа LLM и публичного сервиса. Скриншот или mock не подтвердят их работу.

Ориентир: 3 минуты после появления доступа.

5. Eval и разбор ошибки

Eval не запускали. Процента качества и фактического разбора ошибки пока нет.

Набор должен включать правильный факт с неверной ссылкой, неизвестную дату, инструкцию внутри материала, нехватку времени и сбой MCP.

Как будет оформлена ошибка

Сырой ответ → поддерживающий материал → проверка с evidence → установленная причина → исправление → повтор того же случая. Пока это шаблон, не полученный результат.

Timeout и неответ входят в знаменатель. Offline/MCP/live/hosted учитываются отдельно.
