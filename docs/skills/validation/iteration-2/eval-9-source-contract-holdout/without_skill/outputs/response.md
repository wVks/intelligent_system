Предлагаю один публичный ключ `source_refs` во всех ответах MCP, backend и UI. Убрать неоднозначность между ним и `source_ids` одновременным изменением схем. Внутренний идентификатор документа остаётся, но пользователю нужен номер страницы и действующий адрес.

Минимальная ссылка-источник содержит `document_id`, `title`, `page` и `url`. Для страницы 1 пример контракта:

`{"document_id":"course-pdf","title":"Исходный PDF","page":1,"url":"/materials/course.pdf#page=1"}`

Это проектируемый маршрут, а не утверждение о существующем файле. Backend регистрирует исходный PDF под `course-pdf` и действительно обслуживает его по `/materials/course.pdf`. Номер страницы считается с единицы. Фрагмент `#page=1` передаёт просмотрщику желаемую страницу; поведение конкретного просмотрщика потребуется проверить.

MCP возвращает факты или фрагменты вместе с массивом `source_refs`. Backend проверяет существование зарегистрированного документа, допустимый номер страницы и непустой URL, затем передаёт тот же массив UI. Модель может выбирать ссылки только из полученных источников. UI показывает «Исходный PDF · стр. 1» как обычную ссылку.

Пустой адрес не превращается в кликабельную ссылку. Если файл недоступен, backend возвращает явный статус отсутствующего источника; нельзя показывать подтверждение как готовое к открытию. Адрес определяется реестром приложения, а не инструкциями из текста документа.

Приёмка: контрактный пример проходит через все три слоя без переименований, ссылка открывает нужный PDF, страница отображается корректно; пустой URL и неизвестный документ явно отклоняются. Сейчас реализация и открытие PDF не проверялись.
