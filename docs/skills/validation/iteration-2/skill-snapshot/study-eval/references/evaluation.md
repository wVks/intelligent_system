# Eval: исходы, доказательства и агрегация

## Уровни проверки

1. Unit/offline: валидаторы, расчёт часов, обработка ошибок, fake provider.
2. MCP integration: настоящий клиент, discovery и call; протокольный in-memory
   тест плюс smoke выбранного stdio/HTTP транспорта.
3. Live: настоящий провайдер модели с настоящими инструментами и источниками.
4. Hosted smoke: пользовательский сценарий по публичному URL.

Отмечай уровень для каждого прогона. Зелёный fake provider не доказывает уровни 3–4.
Не меняй поставщика/модель и prompt одновременно с retrieval: иначе причина
изменения результата останется неизвестной.

## Что считать успехом

Проверяй исход, допускающий разные верные формулировки и допустимые tool paths:

- Факт: значение соответствует источнику, ответ содержит необходимые части.
- Источник: существующий фрагмент действительно поддерживает это значение.
  Правильный ответ с неподходящей ссылкой проваливает проверку источника.
- Неизвестное: отсутствие даты/сведений признано, предположение не выдано за факт.
- План: суммарные часы, даты, зависимости и выполнимость проверены кодом.
- Инструменты: разрешённые имена, валидные аргументы, обработка `isError`,
  ограничение цикла и общего времени. Ошибка инструмента не превращается в факт.
- Материал со встроенными инструкциями остаётся данными.

Сохраняй сырой ответ и trace рядом с оценкой. Для содержательной проверки текста
используй ревью по рубрике или независимого судью с калибровкой на размеченных
примерах. Самооценка модели и ключевые слова не являются эталоном.

## Формат для score_eval.py

Манифест заранее задаёт полный знаменатель. Минимальный пример:

```json
{
  "dataset_id": "study-v1",
  "cases": [{
    "id": "lms-links", "critical": true,
    "checks": ["factual_accuracy", "source_support"]
  }]
}
```

Результат содержит оценки уже выполненных проверок:

```json
{
  "dataset_id": "study-v1", "run_id": "offline-example", "mode": "offline",
  "cases": [{
    "id": "lms-links", "error": null,
    "checks": [
      {"name": "factual_accuracy", "passed": true,
       "evidence": "Проверяющий сопоставил обе ссылки с fixtures/material-p1.txt"},
      {"name": "source_support", "passed": false,
       "evidence": "В ответе указана страница 2, исходное требование на странице 1"}
    ]
  }]
}
```

Допустимые mode: `offline`, `mcp`, `live`, `hosted`. Используй отдельный файл на
уровень/конфигурацию. `error` — null либо непустая строка; при ошибке весь случай
провален. Evidence — конкретное подтверждение оценки, не «всё хорошо».
Программа вычисляет долю пройденных проверок и случаев; пропуски включены в
полный знаменатель. Все critical cases должны проходить независимо от среднего.

## Отчёт и повторный прогон

Запиши дату, версии зависимостей/приложения, материалы, конфигурацию, режим,
число случаев и повторений, сырые результаты и ошибки. Критерии приёмки задавай
до запуска. Разбирай фактические классы ошибок, а не обещай максимальную оценку.

Методические источники: [оценка агентных систем](https://www.anthropic.com/research/demystifying-evals-for-ai-agents),
[MCP testing](https://py.sdk.modelcontextprotocol.io/get-started/testing/).
