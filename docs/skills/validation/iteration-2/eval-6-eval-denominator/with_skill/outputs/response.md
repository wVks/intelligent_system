Из 30 запланированных случаев 24 завершились успешно по предоставленной сводке: **24/30 = 80%**. Четыре timeout и два отсутствующих результата входят в знаменатель как неудачи. Всего неуспешны 6/30, то есть 20%. «100% по 24 ответам» скрывает неответы и не описывает весь прогон.

Это результат режима **offline с fake provider**. Он может характеризовать проверенные ветви управления и валидаторы, но не качество подключённой LLM, настоящий MCP или доступность сервиса. Кроме того, слово «успешно» требует основания: если 24 ответа лишь получены без ошибки, 80% — доля завершений; качество фактов и ссылок ещё не измерено. Нельзя восстановить доказательства из одной агрегированной цифры.

Для повторения нужен неизменный манифест всех 30 ID и заранее определённых проверок, версия fixtures, конфигурация fake provider, версия кода/зависимостей, фиксированная дата и Europe/Moscow. Результаты сохраняем по каждому ID с сырым ответом, trace, error и evidence проверяющего. Для timeout пишем ошибку; для двух неответов — явную запись отсутствия результата. Пропуски не удаляются из манифеста.

После заполнения подтверждённых оценок запустить `python3 .agents/skills/study-eval/scripts/score_eval.py dataset.json results.json`. Этот агрегатор не проверяет правдивость самостоятельно. Затем повторить тот же набор и отдельно разобрать причины четырёх timeout и двух неответов; baseline сравнивается при одинаковой конфигурации. Реальные MCP, live LLM и hosted smoke получают отдельные результаты. Сейчас выполнен только расчёт по данным запроса; исходные ответы и тестовый runner не предоставлены, новый прогон не запускался.
