Сначала воспроизвести два симптома отдельно: модель повторяет одинаковый поиск; MCP недоступен до первого вызова или отключается во время запроса. Записать номер раунда, инструмент, длительность и тип результата без ключей и лишнего текста материалов. По описанию вероятны две причины: цикл не ограничен, а ошибка MCP превращается в пустой список.

Первая точечная правка — ограничение цикла backend: например, четыре раунда инструментов, общий срок ответа 60 секунд и отдельный таймаут вызова. Повтор одинаковых аргументов учитывается в лимите. После исчерпания бюджета запрос завершается понятным сообщением о невозможности закончить проверку; бесконечных повторов нет. Точные значения затем подбираются по замерам.

Вторая правка — сохранить разные состояния: успешный результат с пустыми `items`, `timeout`, `unavailable`, ошибка аргументов. При недоступном MCP чат сообщает, что получить задания сейчас не удалось. Утверждение «заданий нет» допустимо только после успешного обращения к данным.

Проверки: сценарий повторяющей поиски модели завершает цикл в пределах бюджета; отключение MCP не даёт ложного пустого результата; настоящий пустой поиск остаётся успешным. Дополнить unit-тест протокольным тестом: отдельный MCP-процесс, инициализация, получение списка инструментов и вызов `search_materials` через клиент. Fake-модель допустима для проверки управления циклом, но её нужно пометить. После исправлений потребуется один прогон с подключённой моделью. Сейчас воспроизведение и тесты не выполнялись: код не предоставлен.
