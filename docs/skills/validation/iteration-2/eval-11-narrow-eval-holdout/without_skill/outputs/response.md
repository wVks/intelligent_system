Минимальный регрессионный случай: общий доступный бюджет — 120 минут; план содержит пять последовательных задач по 60 минут каждая. Суммарно требуется 300 минут. Все длительности положительные, единица измерения едина, поэтому причина ошибки здесь только превышение бюджета.

Вход теста в нейтральном формате:

```json
{
  "available_minutes": 120,
  "tasks": [
    {"id": "a", "minutes": 60},
    {"id": "b", "minutes": 60},
    {"id": "c", "minutes": 60},
    {"id": "d", "minutes": 60},
    {"id": "e", "minutes": 60}
  ]
}
```

Действие: передать этот план валидатору. Проверяемый результат — план отклонён, сообщено превышение общего бюджета: доступно 120, запланировано 300, превышение 180 минут. Конкретное имя поля ошибки можно согласовать с существующим контрактом после получения кода; семантика результата фиксирована уже сейчас.

Ключевое утверждение теста: нельзя принять план лишь потому, что длительность каждой отдельной задачи меньше двух часов. Проверяется сумма всего плана. Сообщение пользователю должно объяснять нехватку времени и предлагать сократить объём или увеличить доступный бюджет. Валидатор не должен молча удалять задачи или считать исходный план допустимым после скрытого исправления.

Это один тест на одну регрессию. Код валидатора не предоставлен, поэтому тест пока не реализован и не запускался. Полный Eval и релизные проверки не выполнялись.
