Первый срез отвечает на один вопрос: «Что отправить в LMS?». Ответ должен перечислить две ссылки: на публичный репозиторий, содержащий README и интерактивную HTML-презентацию, и на работающий сервис. Основание — исходный PDF, страница 1. Дата сдачи неизвестна; в данных хранится `deadline: null`.

Минимальные данные: документ `course-pdf`, страницы 1–3 с извлечённым текстом; задание `submission`, название «Сдача проекта», требования к двум ссылкам, `deadline: null`, ссылки на страницы-источники. Ссылка источника содержит идентификатор документа и номер страницы; backend предоставляет сам PDF для открытия пользователем. Текст требований сохраняется отдельно от инструкций модели.

Маршрут: браузер → `POST /chat` FastAPI → подключённая LLM → запрос инструмента через MCP-клиент backend → MCP-сервер читает SQLite → результат с происхождением фактов → LLM формирует ответ → backend возвращает текст и источники → UI показывает ответ и открываемую страницу PDF.

Планируемый минимум файлов: `app/main.py`, `app/llm.py`, `app/mcp_client.py`, `mcp_server.py`, `schema.sql`, `static/index.html`, файл зависимостей и исходный PDF. JavaScript и стили первого экрана можно оставить внутри HTML.

Приёмка: после воспроизводимого запуска реальный запрос в чате проходит через MCP и подключённую модель, перечисляет обе ссылки, цитирует страницу 1 и не придумывает дату. Проверяются журнал вызова инструмента и открытие PDF. Сейчас это проектирование: приложение и проверка ещё не выполнены.
