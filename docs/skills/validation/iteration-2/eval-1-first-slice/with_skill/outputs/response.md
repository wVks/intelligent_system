Первый срез — один вопрос «Что отправить в LMS?» и подтверждённый ответ: две ссылки, на публичный репозиторий с README и интерактивной HTML-презентацией и на работающий сервис. Основание — страница 1 PDF. Приложение пока отсутствует; ниже проект реализации.

Данные: одно задание `final-project`, курс `project-course`, `due_date: null`, `due_at: null`. Требование содержит `source_ids: ["project-pdf-p1"]`. В каталоге `sources` нужны название PDF, страница 1, точная выдержка и URL, который backend создаст для просмотра PDF. Это реальные требования из предоставленного текста; оценки трудоёмкости сюда не включаем.

Маршрут: форма чата → `POST /api/chat` → backend передаёт LLM разрешённые схемы → модель запрашивает `get_assignment` → настоящий MCP-клиент вызывает MCP-сервер → SQLite возвращает задание и источник → результат возвращается модели с исходным ID вызова → backend проверяет ссылки → UI показывает ответ и открываемую страницу 1. Ключ модели остаётся в окружении backend.

Минимум файлов: `pyproject.toml` и lock-файл, `app/main.py`, `app/agent.py`, `app/mcp_client.py`, `app/mcp_server.py`, `app/static/index.html`, `data/seed.json`, исходный PDF и один интеграционный тест. База создаётся воспроизводимо из seed.

Приёмка: обе ссылки названы, цитата поддерживает утверждение, PDF открывается на странице 1. MCP discovery и вызов подтверждены трассой; прямого вызова Python-функции недостаточно. Ошибка MCP отображается ошибкой, неизвестный срок не придуман. Offline-прогон и живой LLM-прогон фиксируются отдельно. Сейчас код и проверки не выполнялись.
