Достоверная формулировка для README: «Офлайн-тесты с mock HTTP и LLM проходят по предоставленной сводке. Обработчики инструментов проверялись прямыми вызовами функций. Протокольная MCP-интеграция и живой чат по публичному адресу не проверены. Ответ `/health` подтверждён только в сообщённых условиях. После рестарта SQLite пересоздаётся; пригодность такого поведения зависит от назначения данных». Заявлять стабильный MCP и готовность к защите пока нельзя.

Прямой вызов Python-функции проверяет обработчик, но обходит MCP discovery, сериализацию, транспорт и lifecycle. Mock LLM не доказывает работу подключённой модели. Успешный `/health` не подтверждает пользовательский сценарий и доступ backend к API провайдера.

Перед сдачей нужны точечные доказательства:

1. Настоящий клиент обнаруживает три разрешённых инструмента, вызывает их через выбранный транспорт и корректно закрывается. Проверяются пустой результат, недоступность сервера, timeout и ограничение цикла. Неизвестное имя/невалидные аргументы не доходят до dispatch.
2. По публичному адресу выполнить чат с реальной LLM: вопрос об LMS, неизвестная дата, открытие подтверждающей страницы PDF. Сохранить безопасную трассу и конфигурацию.
3. Проверить базу после рестарта. Фиксированный демонабор допустимо воспроизводимо создавать заново; пользовательские изменения требуют постоянного тома/хранилища и проверки сохранности контрольной записи.
4. Выполнить чистый запуск по README и Eval, отдельно по уровням offline/MCP/live/hosted; timeout и неответы включить в знаменатель. Приложить реальные ошибки и ограничения.

Также проверить наличие интерактивной HTML-презентации, публичного репозитория и двух ссылок для LMS. Сейчас новые проверки не выполнялись; текст основан на предоставленных фактах, итоговые баллы не назначаются.
