# Итерации

## Черновик v1

Созданы четыре skills с двумя задачами на каждый. Контекст вынесен в project-brief,
постоянные правила — в AGENTS; вспомогательная агрегация — в stdlib Python.
Штатный quick_validate подтвердил формат всех четырёх. Для него PyYAML установлен
только во временный каталог, проект не получил дополнительной зависимости.

## Независимое ревью и корректировки v2

Ревью программ воспроизвело четыре вида ложного успеха:

1. Каталог без SKILL.md пропускался при поиске.
2. UI-метаданные принимались без контейнера interface.
3. Неверные типы prompt/expected_output/expectations принимались как заполненные.
4. Повторяющийся JSON-ключ позволял затереть passed:false значением passed:true.

Причины исправлены, добавлены регрессионные проверки. Включая сопутствующие
проверки дублей/нечисловых JSON-констант и нестрокового mode, проходят 23 теста.

Независимое ревью инструкций выявило два полезных уточнения:

- Согласованы source_ids/каталог sources между build и MCP, добавлен url источника
  и правило его разрешения в реальный маршрут просмотра.
- Полный Eval/Release ограничен областью запроса; отдельная проверка не должна
  запускать создание всей презентации, отчёта и остальных материалов.

Поведенческая оценка сценария сбоя MCP показала ещё один пробел: упоминание
теста неизвестного имени не доказывает проверку до dispatch. В study-mcp добавлен
конкретный инвариант: при неизвестном имени или неверных аргументах счётчик
вызовов MCP-клиента остаётся нулём.

Снимок v1 сохранён до этих изменений. Выводы ревью и сырые результаты доступны
в этой папке. Поведенческие прогоны проверяют инструкции разработчику, а не
качество ещё не созданного приложения.
