Минимальная архитектура: FastAPI backend управляет одним MCP-сервером как stdio-подпроцессом; сервер читает SQLite с одним заданием и фрагментами PDF. Такой транспорт подходит локальному MVP и одному хост-процессу; отдельный HTTP-сервис пока не нужен. Использовать SDK для initialize/discovery/call, согласования протокола и сериализации. Версия SDK не установлена: до реализации зафиксировать её и проверить API по официальной документации; здесь сеть не использовалась.

Три инструмента, строгие JSON-схемы с запретом лишних полей:

- `list_assignments({course_id?: string})` → `{assignments:[{assignment_id,course_id,title,due_date,due_at,source_ids}]}`.
- `get_assignment({assignment_id: nonempty string})` → `{assignment:{...requirements,criteria,source_refs}}`.
- `search_materials({query: string 1..500,limit?: int 1..10=5})` → `{matches:[{assignment_id,source_id,title,page,section,excerpt}]}`.

Стабильные ID; страница ≥1 либо null; неизвестные сроки `null`, дата без времени хранится только в `due_date`. Требования к LMS — PDF, стр. 1; дата сдачи отсутствует. Для UI backend сопоставляет `source_id` с разрешённой ссылкой на исходник. SQLite-запросы параметризованы; модель не задаёт SQL, путь или MCP URL. Все инструменты читающие.

Backend в lifespan открывает соединение, вызывает discovery и пересекает каталог с allowlist из трёх имён; схемы передаёт LLM. Модель предлагает вызов, backend проверяет аргументы, вызывает MCP, возвращает фактический результат с тем же call ID и получает ответ с источниками. Ключ и конфигурация модели — серверное окружение. Предлагаемые пределы: 4 tool calls, 30 секунд на запрос, ограниченный контекст; значения конфигурируются. Отмена/timeout закрывают ресурсы.

`matches: []` означает успешный пустой поиск. Неизвестный ID, ошибка валидации, ошибка хранилища и недоступный транспорт — разные статусы; сбой никогда не превращаем в «заданий нет». Логи: request ID, имя, безопасные аргументы, статус, длительность, source IDs; без ключей и полных приватных материалов.

Доказательство MCP: (1) unit-контракты; (2) настоящий SDK-клиент выполняет initialize, list tools и call на изолированной базе; (3) smoke запускает stdio-подпроцесс, получает все три инструмента, вызывает поиск и закрывается; stdout содержит только протокол; (4) fake LLM запрашивает инструмент, получает реальный MCP-result; (5) отдельно live LLM по основному вопросу и неизвестной дате. Прямой Python-вызов обработчика доказывает только unit-логику. Сохраняем версию SDK/транспорта и trace. Сейчас спроектировано, код/протокол/live не запускались.
