# StudyNavigator

Статус: локальный черновик материалов сдачи. Существующий README и код в рамках этого снимка не предоставлены; команды и ссылки нельзя считать проверенными. По условию локальный запуск есть, Eval отсутствует, публичный сервис не развёрнут. Дата защиты неизвестна.

## 1. Задача

Учебный веб-ассистент помогает студенту одного курса найти требования задания в материалах и составить план подготовки. Первый проверяемый сценарий: «Что отправить в LMS?» → две ссылки: публичный репозиторий с README и интерактивной HTML-презентацией; работающий сервис (исходный PDF, стр. 1).

## 2. Пользователь и сценарий

Студент задаёт вопрос в веб-чате, получает ответ с источником и страницей. При неизвестном сроке ассистент признаёт отсутствие даты, просит уточнить её; относительный план обозначает предположением. Неполученный ответ инструмента не означает отсутствия заданий.

## 3. Границы MVP

Один курс, исходный PDF, чат и список заданий; читающие инструменты list_assignments, get_assignment, search_materials. Без реальной LMS, аккаунтов, уведомлений. Выбран стек Python/FastAPI, SQLite, HTML/CSS/JS, LLM по API, собственные MCP-сервер и клиент.

Готовность основного сценария: корректные две ссылки по смыслу с подтверждением стр. 1, настоящий MCP-обмен и LLM, корректная ошибка недоступности, null для отсутствующего срока. Это целевые критерии, их выполнение не подтверждено. Согласование темы преподавателем не подтверждено.

## 4. Архитектура

Целевая схема (требует сверки с кодом):

```text
Браузер → FastAPI /api/chat → адаптер LLM
                              ↕ tool calls/results
                         MCP-клиент
                              ↕ MCP/stdio
                         MCP-сервер → SQLite → фрагменты PDF
```

Источник содержит source_id, страницу/раздел и выдержку; ссылка рядом с утверждением открывает источник. Секреты только в серверном окружении.

## 5. MCP-интеграция

Предлагаемый транспорт локального MVP — stdio управляемого подпроцесса. Фактические транспорт и SDK не проверены. Инструменты: list_assignments (список), get_assignment (требования/критерии), search_materials (фрагменты). Клиент получает каталог через протокол, пересекает с allowlist и передаёт модели фактические результаты с call IDs.

Прямой вызов Python-функции не доказывает MCP. Требуются отдельные discovery/call настоящим клиентом, smoke выбранного транспорта и обработка ошибок. Эти результаты пока отсутствуют.

## 6. AI-логика

Провайдер, модель и версия конфигурации не указаны: ключ недоступен, живой вызов не проверен. План: модель выбирает разрешённый инструмент и формулирует объяснение по найденному; код проверяет ссылки, даты, часы плана, лимиты вызовов/времени. Документы и tool results — данные, вложенные инструкции не исполняются. due_date/due_at неизвестны → null.

## 7. Запуск и развёртывание

По условию сервис запускается локально, но команды, lock-файл и конфигурация не представлены. Поэтому ниже порядок подтверждения, а не выдуманная рабочая инструкция:

1. Из реального репозитория указать точный commit, поддерживаемый Python, lock и команды установки.
2. Зафиксировать безопасный .env.example с реальными именами настроек, seed PDF/SQLite и точные команды создания базы/старта.
3. Выполнить их в чистом временном каталоге; записать команды и коды выхода.
4. Ключ LLM установить в окружение сервера, не в браузер/репозиторий/логи.
5. На выбранном доступном хостинге проверить порт/команду старта, доступ к модели и способ хранения SQLite. Не выбирать поставщика без доступов и кода.
6. После деплоя проверить пользовательский чат, неизвестный вопрос и рестарт, сохранить URL и дату проверки.

Публичный URL сервиса: отсутствует. Публичный URL репозитория: не предоставлен. Чистый запуск: не проверен. Не загружать фиктивные URL в LMS.

## 8. Eval и ошибки

Eval не запускался. Процент качества и утверждение о стабильности отсутствуют. Подготовленный минимальный набор: LMS/стр.1; неизвестная дата; верный факт с неверной ссылкой; инструкция внутри материала; транспортный сбой; превышение бюджета плана. Манифест/checks фиксировать до запуска.

Для фактического прогона сохранить дату/зону, версии, mode (offline/mcp/live/hosted), модель/настройки, сырой ответ, trace, каждую оценку и evidence. Timeout и отсутствие ответа входят в знаменатель. Offline/mock не доказывает живую модель или публичный сервис. Фактические ошибки и изменения заполнить после запуска, не подменять их благополучными примерами.
