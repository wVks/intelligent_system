# StudyNavigator: контекст разработки

## Источник и обязательный результат

Источник задания: [Личный проект.pdf](../Личный%20проект.pdf), 3 страницы.
Этот файл — первичный источник; приведённые ниже технические решения — выбор
для нашего MVP, а не дополнительные требования преподавателя.

Страница 1 требует публичный репозиторий, подключённую LLM, MCP-интеграцию,
пользовательский интерфейс, развёрнутый сервис, Eval с разбором ошибок,
README.md и интерактивную HTML-презентацию для защиты до 10 минут.
В LMS передаются ссылка на репозиторий с README/презентацией и ссылка на сервис.

README: название/задача; пользователь/сценарий; границы MVP; архитектурная схема;
схема MCP; AI-логика; запуск/развёртывание; результаты Eval/ошибки; источники.

Страницы 2–3: пять критериев по 10 баллов, всего 50:
задача и границы; MCP; сервис и хостинг; качество и воспроизводимость; демо и ответы.
Для 10 баллов за постановку задачи требуются MVP, критерии готовности и согласование
с преподавателями. Подключение только чужого готового MCP не заменяет реализацию
собственного сервера, указанную в критерии MCP.

В PDF не указаны срок сдачи, название курса, язык программирования и конкретная LLM.
Не выводить дату сдачи из текущей даты или названия файла.

## Выбранный MVP

Пользователь — студент одного курса. Сценарий: найти требования и критерии задания,
узнать известные сроки, получить план подготовки с учётом свободного времени.

- Веб-страница с чатом и списком заданий; ответы по-русски с указанием источников.
- Заранее подготовленные материалы; данный PDF — первый реальный источник.
  Дополнительные примеры явно маркируются как демонстрационные.
- Три read-only MCP-инструмента: `list_assignments`, `get_assignment`, `search_materials`.
- LLM выбирает инструменты и объясняет результат; даты, суммы часов и ограничения
  плана проверяет обычный код. Неизвестные данные остаются неизвестными.
- Один серверный backend, SQLite с воспроизводимыми seed-данными, простой frontend.
  Предпочтительный стек — Python/FastAPI. Версии зависимостей нужно проверить и
  зафиксировать при реализации, провайдер и модель пока не выбраны.
- База доступна агенту через MCP-клиент. Backend может пользоваться отдельными
  сервисными функциями для UI, но ими нельзя подменять MCP в AI-сценарии.

Первая версия не включает реальную LMS, роли/аккаунты студентов, уведомления,
календарные интеграции и разбор произвольных загружаемых PDF.

## Первый вертикальный сценарий и готовность

Запрос: «Что отправить в LMS?» → реальный MCP-вызов → требования со страницы 1 →
ответ: две ссылки (репозиторий с README/HTML и работающий сервис) с источником.

Другой запрос: «Когда сдавать?» → поиск сведений → дата не найдена → понятное
сообщение и запрос даты у пользователя. Из предположения нельзя получать факт.

Предлагаемые инженерные критерии, ещё не результаты: все критические сценарии
проходят, проверены реальные list/call MCP, пройден живой сценарий с моделью,
сервис доступен по ссылке, seed/конфигурация позволяют повторить запуск,
Eval содержит реальные ответы, источники, трассы инструментов и разбор ошибок.
Объём Eval (например, 30 случаев) определяется при разработке, PDF его не задаёт.
