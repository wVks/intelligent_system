# Этапы 2–3: карточка задания и план

Дата: 27 октября 2026 года. Изменения локальные. Этапы реализованы;
реальная модель по API остаётся непроверенной до этапа 5.

## Результат

- Общая карточка: цель, результат сдачи, требования, критерии, известный срок,
  вопросы и задачи. Документальные сведения имеют source_ids/origin=document;
  исправления пользователя получают user без выдуманного источника PDF.
- Анализ читает исходники через настоящий MCP get_assignment. Live-адаптер
  запрашивает JSON и проверяет схему/ссылки. Offline открывает пустую ручную форму,
  а не изображает понимание произвольного документа. Тесты модели — фикстуры.
- Подтверждение сохраняет карточку и версию. Устаревший confirm/plan даёт 409;
  ошибка анализа не затирает прежние данные. Сохранена изоляция сессий и MCP.
- Задачи конкретной карточки, редактирование названий/минут и выполненного,
  последовательное расписание, дефицит. Без предложенных задач модели код
  предлагает явный шаблон из требований: по 60 минут и проверка результата
  30 минут. Это предварительные оценки. MCP/Eval/README-шаблон остаётся
  только для исходного примера personal-project.
- Правка длительности становится user. Всё выполнено → feasible, ноль работы
  и дефицита, schedule=[]. При явной дате начала горизонт ограничивается
  известным сроком; текущая дата автоматически не подставляется.
- Чат нового задания использует его карточку и FTS5/MCP. Offline показывает
  происхождение и цитаты, а не чужие факты о LMS/50 баллах/MCP. Пользовательский
  срок объясняется как ввод пользователя, без поддельной документальной ссылки.
- UI: ручной/AI-разбор, редактирование/подтверждение, источники, отмена и ошибки
  версии, редактор задач/минут/выполненного. Изменения скрывают устаревший план.

## Контракты и ограничения

POST /api/assignments/{id}/analyze с {} возвращает assignment/card/revision,
mode, analysis_kind, notice, trace и usage либо null. Confirm принимает card/revision.
Plan принимает card_revision и полный список задач; выполненное помечается явно.

Внешний API: Chat Completions, function tools, JSON mode. Один повтор временного
сбоя внутри исходного timeout, 401/403 без повторов; безопасные 429/timeout.
Usage возвращается только из реального ответа API; расходы не выдумываются.

Chat JSON остаётся 16 KiB; confirm отдельно ограничен 96 KiB, plan — 32 KiB,
multipart — прежними 10 MiB файлов. Материалы анализа: до 24000 символов JSON
плюс фиксированная схема. Контекст чата нового задания — 32000 символов,
исходного примера — 16000; исходники читаются поиском, не дублируются с карточкой.
Сохраняются исходники, карточка, версия и происхождение; диалоги и отметки
завершённости не становятся серверным личным прогрессом.

## Проверки

```sh
.venv/bin/python -m pytest tests/app -q
```

**177 passed in 43.37s** после итоговых исправлений. Включены старые регрессии,
test_cards.py, test_cards_api.py, test_provider_analysis.py и расширения
test_planner.py/test_agent.py. Сетевой адаптер проверен через MockTransport,
а MCP — настоящими stdio list/call. Это не live Eval качества модели.

Независимое ревью выявило два случая; добавлены регрессии и исправления:
пользовательский срок канонизируется до требования документальной ссылки;
полностью завершённые задачи дают нулевой план даже после срока.

Через запущенный HTTP-сервер пройден путь: загрузка → ручная карточка через MCP →
ввод/подтверждение → задачи → 300 минут при доступных 120 → дефицит 180 →
всё выполнено → пустой план. Чат получил фрагменты своего PDF, чужая сессия
не получила задание; новая версия отклонила старый план. После полного рестарта
карточка/версия/PDF сохранились, выполненность не сохранилась. Проверочные
записи удалены, сервер оставлен запущенным на http://127.0.0.1:8000.

JavaScript и 83 DOM ID/подписи/формы проверены статически. Chrome получил новые
HTML/CSS/JS и данные с 200, но полный визуальный прогон карточки и редактора
задач не завершён: нативная автоматизация возвращала пустое окно и timeout.
Это не записано как успешная визуальная приёмка; проверка полного пути,
клавиатуры и узкого экрана остаётся этапом 4.

Ключ в .env.example пустой. Внешних LLM-запросов/расходов, публикации и Git push
не было. Смысловая точность AI-карточки, источников и свободного текста требует
реальной модели и Eval на этапе 5; хостинг/Docker/HTML-защита — этап 6.
