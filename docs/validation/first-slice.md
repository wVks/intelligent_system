# Первый локальный срез StudyNavigator

Дата: 26 октября 2026 года. Изменения этого этапа сохраняются локально;
публичный деплой и Git push не выполнялись.

## Реализовано

- 160 решений и критериев проверки в локальном `docs/development-answers.local.md`.
  Файл исключён из Git; неизвестные даты, согласование и доступы не выдуманы.
- Python 3.12, зафиксированные зависимости в `uv.lock` и runtime `requirements.lock`.
- Воспроизводимый SQLite/FTS5-каталог из исходного PDF с проверкой SHA-256.
- Собственные MCP-сервер и клиент, реальные discovery/call по stdio.
- FastAPI, агент с ограничениями, проверка typed facts и источников,
  отдельные offline/live-провайдеры, обработка неизвестной даты.
- Веб-чат, просмотр источника и PDF, история в памяти вкладки, отмена,
  относительный план в целочисленных минутах с проверкой дефицита времени.

## Найденные ошибки и итерации

1. **Начальный offline-прогон — 22/30.** Семь проблем распознавания намерений:
   частные баллы смешивались с общими и неизвестные сведения получали общий
   ответ. Один критерий оценщика слишком узко требовал только call-limit,
   хотя раньше корректно срабатывал context-limit. Оценщик уточнён для обоих
   допустимых защитных исходов; остальные ожидания сохранены.
2. **После исправлений — 28/30.** Длительность защиты смешивалась с баллами,
   а физическое место защиты — с аудиторией слушателей. Признаки разделены.
3. **Итог — 30/30.** Ранние результаты сохранены в `var/eval-offline-initial.json`
   и `var/eval-offline-before-final-intents.json`; неудачи не удалены.

Дополнительные содержательные регрессии из независимого ревью:

- Финал после одного поиска мог обходить проверку метаданных задания.
  Теперь сначала требуется выбранное `get_assignment`, чужой ID отклоняется.
- Модель могла написать выдуманную дату в тексте со статусом `insufficient_data`
  и пустыми facts. При неизвестной дате ответ канонизируется из метаданных.
- Лимит контекста применялся к одному результату вместо суммы. Теперь он общий;
  при нехватке места сначала удаляется старая история.
- SDK cleanup мог оборачивать ошибку приложения в `ExceptionGroup`.
  Ошибка сохраняется, а stdio закрывается в владеющей задаче.
- Непредвиденный сбой провайдера давал plain HTTP 500. Теперь возвращается
  безопасный JSON с request ID, без текста исключения или ключей.

Проверены также роли истории, тело свыше 16 KiB (включая streamed), нулевой
dispatch для неверных аргументов, timeout/disconnect и освобождение MCP-ресурсов.

## Ограничения результата

Offline-провайдер детерминирован и не является LLM. Его успешные ответы не
измеряют качество живой модели. Synthetic injection cases проверяют защитный
код, а не устойчивость языковой модели к prompt injection.

Typed facts и происхождение проверяются кодом; истинность и полнота каждой
фразы свободного live-текста требуют независимого содержательного Eval.
Набор виден разработчикам; метка holdout не делает текущий прогон слепым.
Настоящая задержка живой модели, контейнерная сборка, мобильное отображение
в браузере и доступность публичного сервиса ещё не подтверждены.

Следующий этап: выбрать реально доступный провайдер/модель, настроить серверный
секрет, отдельно выполнить live-прогон и разбор ошибок; затем проверить Docker,
размещение и подготовить окончательную HTML-защиту. Сроки и согласование темы
требуют фактов от пользователя или преподавателя.
