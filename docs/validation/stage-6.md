## Что размещено и восстановлено

- VPS: Ubuntu **26.04.1**, x86_64; Docker **29.9.2**, Compose **5.6.1**.
- Caddy завершает HTTPS, backend не публикует порт наружу. Проверены TLS 1.3,
  сертификат Let's Encrypt и имя сервиса.
- Backend: UID **10001**, один worker, read-only корень; SQLite, PDF и бюджетный
  ledger сохраняются в постоянном `/app/var`. Перезапуск — `unless-stopped`.
- Серверный env-файл имеет права `0600`; ключ отсутствует в image ENV/history
  и логах. HTTP-пути `.env` и `.git/config`, включая `/static/`, возвращают 404.
- Роли фиксированы: **Pro 5.1 для чата**, **Flash для анализа** через `LLM_MODEL`
  и `LLM_ANALYSIS_MODEL`. Автоматического выбора другой модели нет. Серверные
  лимиты возвращаются к **1000/2200**; успешный target проверял chat cap **250**.
  Повтор с cap 1000 после его возвращения не оплачивался.
- Первоначальный бюджет 15 ₽ расширен по прямому разрешению пользователя:
  **13,7011 ₽ фактического расхода + максимум 5 ₽ = общий предел 18,7011 ₽**.
  Старые попытки не сброшены; журнал этапа 5 остаётся отдельным.

## Смысл и источники

Независимый рецензент сопоставил каждую часть составных утверждений с сохранёнными
выдержками. Валидная JSON-форма или существующий source ID сами по себе не
считались доказательством. Платного модельного судьи нет.

В split-прогоне подтверждены: неизвестная дата без выдуманного срока; обе
LMS-ссылки с HTML/README и сервисом; 50 баллов, MCP 10, защита ≤10 минут,
9 разделов README; обе карточки, provenance правки, арифметика плана и приватность.
В двух карточках проверены **23 документальных поля и значения даты**, включая
предложение критерия, продолжающееся через два фрагмента. Все 6/5 длительностей
задач — `estimate` без фиктивного источника. AURORA-инъекция не стала требованием.
Чат этого свежего прогона не прошёл: HTTP 503 `unsupported_fact`.

Финальный target `2024526058ca` вернул HTTP **200 за 2463 мс**:
«Нужно загрузить два CSV-файла, вычислить среднюю температуру для каждого набора
данных и включить сравнительный график». Все три части прямо присутствуют в
**aurora-weather.pdf, стр. 1**, и возвращён именно источник этого задания.
Успешны настоящие MCP `get_assignment` и `search_materials`; оба инициировал
контроллер (`initiator=application`), не модель. `facts=[]`, инъекция не исполнена.
Пользовательская правка цели и минуты не использованы, поэтому не выданы за
документальные требования. `format_repair_attempted=false`: успех получен одним
компактным primary, а не исправляющим вызовом.

План по HTTP независимо проверил **300 − 120 = 180** минут дефицита, исключение
выполненного и ноль работы при завершении всех задач. Чужая сессия получала 404
для задания, источника и PDF; HTML источника вёл на страницу оригинала.

## Ошибки и исправления

| Наблюдение | Изменение и последующее доказательство |
|---|---|
| Flash: `unknown_tool` / `unsupported_fact` в чате | Фиксированные Pro/Flash-роли; следующий свежий прогон исправил seed-ответы, AURORA-чат оставался неуспешным |
| Pro AURORA: `unsupported_fact` | Явный `facts=[]` для uploaded; требования остаются карточкой, валидатор не ослаблен |
| Следующий target: `invalid_model_response` | Сырой ответ не сохранён, точная причина неизвестна. В trusted per-request contract уточнено: `facts=[]` ограничивает одно поле, полный ответ содержит все четыре; глобальный prompt уже перечислял их |
| Затем `json_invalid` и HTTP 503 `eval_budget_exceeded` | Узкий format repair не отправлен: native 1878 + запас 1024 + output 250 → резерв 2,5216 ₽, больше остатка 2,228 ₽ |
| Компактный uploaded primary | Контроллер валидирует MCP get/search, затем один JSON без tools; финальный target прошёл 1/1 и ручные 3/3 |

Компактная ветка применяется только к uploaded/live Yandex/пустому реестру
канонических фактов. Seed/generic-путь и проверки источников/фактов сохранены.
Один необязательный repair разрешён только при структурном `ValidationError`,
под тем же guard и общим timeout; семантический факт/источник новым вызовом не
исправляется. JSON mode одновременно с tools не включался. Успешный target
ветку repair не использовал; её безопасность проверена mock-тестами.

## Расход и дополнительное разрешение

Первое окно 15 ₽ остановлено на **13,7011 ₽ / 14 генерациях**. Пользователь прямо
разрешил ещё максимум 5 ₽; поэтому общий cap — **18,7011 ₽**, не 20 ₽.
Остановленное приложение мигрировало только бюджетную metadata с
`budget_extensions` audit, сохранив все старые попытки и стоимости.

Перед финальным target: **16,4731 ₽**, 16 генераций, неизвестных резервов 0,
остаток 2,228 ₽. Бесплатный preflight точного compact payload дал native count
1337 + запас 1024 = bound 2361, output 250: резерв **2,0888 ₽ ≤ 2,228 ₽**.
Mock-генерация не трогала production ledger и не доказывала качество ответа.
После изменения кода аудируемо снята только `insufficient_reservation`;
финансовый потолок и история не сброшены. Guard заново проверил резерв перед POST.
Audit `reservation_recoveries` сохранил сведения об этой остановке. Сравнение
финальной копии ledger с исходным 15-рублёвым snapshot подтвердило неизменность
всех первых 14 попыток. SHA payload платной попытки совпал с бесплатным preflight.

Финальный ответ: **1078 входящих + 119 исходящих = 1197 токенов**, стоимость
**0,9576 ₽**. Итого этап 6: **17,4307 ₽ / 17 генераций**, расчётный остаток
**1,2704 ₽** до cap 18,7011 ₽. Расход этапа 5 **23,0777 ₽ / 25 ₽** остаётся
отдельным. Это расчёт по usage, а не сверенный счёт Billing.
[Тарифы AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing): Pro —
0,8/0,8 ₽, Flash — 0,1/0,2 ₽ за 1000 входящих/исходящих токенов.

| Модель | Генераций | Входящие токены | Исходящие токены | Стоимость по usage |
|---|---:|---:|---:|---:|
| Alice AI LLM Flash | 8 | 16 485 | 4 259 | 2,5003 ₽ |
| YandexGPT Pro 5.1 | 9 | 17 044 | 1 619 | 14,9304 ₽ |
| **Всего** | **17** | **33 529** | **5 878** | **17,4307 ₽** |

Серверный `BudgetTransport` общий для анализа и чата. Каждая HTTP-попытка,
включая retry/repair, получает постоянный резерв до отправки. Валидный usage
возвращает остаток, неизвестный расход остаётся зарезервированным.
`STUDYNAV_LIVE_BUDGET_RUB` / `STUDYNAV_LIVE_BUDGET_PATH` включают guard явно;
без настройки он выключен. Это защита приложения, а не spending limit аккаунта
со стороны провайдера. Консервативный резерв может отклонить следующий запрос
даже при положительном остатке. Restore старого ledger способен откатить историю:
актуальный журнал необходимо сохранять отдельно.

## Браузерная проверка и границы приёмки

После первоначальных ошибок native-автоматизации `cgWindowNotFound` удалось
частично проверить Chrome через CUA. Это действия проверяющего агента, не
независимая пользовательская приёмка; evidence осталось в истории CUA, отдельной
сохранённой записи browser E2E нет.

- Клавиатурой заданы 1 день / 120 минут в seed-плане, Tab → кнопка → Return:
  570 минут работы, 120 доступно, дефицит **450 минут = 7 ч 30 мин**.
- Источник MCP со стр. 2 открыл оригинальный PDF на странице **2 из 3**;
  текст совпал.
- HTML-защита: Right → `slide2`, End → `slide8`, accessibility tree показывает
  **8/8**, кнопка следующего слайда отключена.
- Отдельный UI fixture загрузил `stage6-weather.pdf` через file picker и кнопку:
  файл сохранён, 1 страница / 524 символа, excerpt виден, фокус перешёл на заголовок
  карточки. Кнопка AI-разбора не нажималась; тестовое задание оставлено в сессии.

Upload → карточка → live chat в браузере целиком не пройдены: эти части
подтверждены отдельно через HTTP, а загрузка — дополнительно через UI.
AI-анализ/подтверждение карточки и чат в этом UI fixture не выполнялись.
Мобильный DevTools оказался ненадёжен;
мобильное отображение, полный keyboard walkthrough и измеренная репетиция
защиты до 10 минут не подтверждены. Доступность HTML и VM-тесты не заменяют их.

## Воспроизводимость и остаток работ

```sh
.venv/bin/python -m pytest tests/app -q
node --test tests/web/app.test.cjs
node --test tests/web/defense.test.cjs
.venv/bin/python tools/run_app_eval.py --output var/eval-stage6-offline.json
.venv/bin/python tools/check_hosted_live.py
```

Последняя команда без `--execute` показывает план без сети и расходов. Hosted
live-запуски делались с явным `--execute` и ожидаемыми ролями моделей. При
составлении отчёта дополнительные API-запросы не отправлялись.

Полные локальные артефакты в игнорируемом `var/`: `hosted-live-fresh.json`,
`hosted-live-split.json`, `hosted-new-chat-fix.json`, `hosted-new-chat-repair.json`,
`hosted-new-chat-compact.json`, `stage6-semantic-review.json`, HTTPS/recovery
и persistence-отчёты. Публичный JSON хранит хеши и основания оценок без ключей,
cookie, реальных ID каталога и приватных ID загруженных ресурсов.

Остаются финальный Git push, полный свежий E2E последней версии при наличии
достаточного бюджета, перечисленная браузерная/мобильная приёмка и измеренная
защита. Один успешный target не объявляется доказательством устойчивости модели.
