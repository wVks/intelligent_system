# Этап 4: цельный пользовательский сценарий

Дата: 27 октября 2026 года. Локальная проверка, режим `offline`, без API-ключа.

## Изменения

- Несохранённая карточка защищена от случайного переключения задания.
  Пользователь может подтвердить её или явно отменить правки.
- После загрузки переход к карточке происходит только при успешном получении
  задания. При ошибке остаются сохранённая запись и действие повторного открытия.
- Успешное удаление сразу обновляет известный список; сбой открытия следующего
  задания не возвращает удалённую запись и не блокирует повтор.
- Фокус переходит к карточке после загрузки, к плану после подтверждения,
  в доступное поле после отмены и в цель после отмены правок.
- Длинные названия, ссылки и задачи переносятся, поля плана сужаются;
  боковая панель прокручивается, мобильные кнопки и ссылки увеличены.
- Убрана устаревшая подсказка о недоступности анализа на текущем этапе.

## Автоматическая проверка

```sh
.venv/bin/python -m pytest tests/app -q
node --test tests/web/app.test.cjs
node --check web/app.js
git diff --check
```

Результат: **181 Python-тест** прошёл за 47,95 с; **9 JavaScript-тестов**
прошли. Проверки синтаксиса и пробелов прошли.

Четыре новые Python-регрессии проверяют timeout, отключение клиента,
внешнюю отмену и успешное завершение `connected_request`: операция заканчивает
асинхронную очистку, watcher не остаётся работать, отменённая операция не
выполняет отложенную запись. JavaScript-проверки воспроизводят переходы состояния
и фокуса с небольшой DOM-заглушкой; это отдельные unit-тесты, не браузерный прогон.
На прежнем коде шесть из первых восьми JS-проверок падали; отдельная регрессия
отмены правок также падала до исправления.

## Фактически проверено в Chrome

1. Через форму загружена копия исходного PDF: 3 страницы, 2 873 символа,
   5 фрагментов. Новое задание появилось в списке.
2. Открыта ручная карточка, внесены цель, результат и два требования.
   Пустой срок сохранился как неизвестный; после подтверждения поля получили
   отметку «ваш ввод», появились три последовательные задачи.
3. Первая задача изменена на 300 минут, две другие отмечены выполненными.
   При бюджете 1 день × 120 минут интерфейс показал дефицит 3 часа.
4. Изменение выполнения скрыло старый план. После завершения всех задач
   повторный расчёт показал 0 минут работы и пустое расписание.
5. Вопрос о защите вернул цитаты своих материалов с явной отметкой offline.
   Ссылка открыла исходный фрагмент, а затем PDF: поле номера страницы
   подтвердило **2 / 3**.
6. Правка цели заблокировала чат/план и переход к другому заданию,
   сохранив введённый текст. «Отменить правки» восстановило сохранённую цель.
7. Перезагрузка страницы восстановила подтверждённую карточку и материалы.

Одноразовое задание браузерной проверки затем удалено через локальный Store
по точному ID и названию; пользовательские задания не менялись. Сервис
перезапущен с текущим кодом на `http://127.0.0.1:8000`.

## Границы проверки

Полная приёмка только клавиатурой, точные 360/375 px и повтор после ошибки
загрузки ещё требуют завершения: native-автоматизация Chrome периодически
возвращает устаревшую картину окна, а координатное действие завершилось
`noWindowsAvailable`. На эмуляции 400 px визуально проверены форма загрузки и
карточка без перекрытия полей; это не проверка всего сценария на 375 px.
Отмена серверной работы и ошибочные PDF проверены автоматическими тестами,
быстрая отмена через браузер пока отдельно не подтверждена.

Реальная LLM, смысловое качество её ответов, live Eval и публичный хостинг
относятся к следующим этапам и здесь не проверялись. Git push не выполнялся.
