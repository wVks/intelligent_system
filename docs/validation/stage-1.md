# Этап 1: загрузка и материалы

Дата проверки: 26 октября 2026 года. Этап реализован локально; Git push и
публичное размещение не выполнялись. Следующий этап — AI-карточка задания.

## Результат

- В существующем интерфейсе: форма 1–3 PDF, название, выбранные файлы,
  ожидание, ошибка, отмена, документы/фрагменты, поиск и удаление своего задания.
- Ограничения комплекта: 10 MiB, 16 000 извлечённых символов, 100 страниц;
  страница со слишком большим потоком отклоняется. Поддерживается текстовый PDF.
- pypdf 6.21.2 извлекает текст по страницам в отдельном ограниченном по времени
  процессе. Сканы, пароли, повреждения и превышения дают контролируемые ошибки.
- После успешного извлечения комплект записывается в SQLite и var/uploads/;
  фрагменты до 1200 символов индексируются FTS5 и открывают оригинальную страницу.
- Анонимная cookie разделяет материалы между браузерными сессиями.
  Доступ проверяется на HTTP и MCP; модель не задаёт рабочую область.
- БД и исходники сохраняются после рестарта; seed обновляет только свой пример.
  Ошибка одного файла/индекса не оставляет частично созданного задания.
- Новое задание имеет awaiting_analysis. Требования не выдумываются;
  чат и план по новой загрузке пока возвращают явный assignment_not_ready.
  Исходный подготовленный пример сохраняет прежнее поведение.

Серверная сессия привязана к этому браузеру. Cookie живёт 30 дней;
после её очистки доступ к прежним загрузкам не восстанавливается.
Аккаунты, OCR, AI-анализ, эмбеддинги и фоновые очереди в этап не добавлены.

## Автоматические проверки

Команда из корня проекта:

```sh
.venv/bin/python -m pytest tests/app -q
```

**Фактический результат после последнего исправления: 100 passed in 33.31s.** Набор включает старые регрессии
и новые test_ingestion.py/test_upload_api.py, настоящие MCP stdio list/call.
Тестовые базы и файлы изолированы временными каталогами.

Проверены:

- Несколько PDF, русскоязычный исходный документ, номера страниц и ссылки.
- Валидная загрузка больше 16 KiB при сохранённом лимите JSON 16 KiB.
- Формат, отсутствие текста, пароль, повреждение, лишние файлы/объём/текст.
- Ограничение декодирования сжатых потоков PDF; timeout/отмена убивают и
  дожидаются процесса извлечения, который не пишет БД или файлы.
- Полный откат при смешанном комплекте и при ошибке записи индекса.
- Изоляция списка, задания, поиска, источника, PDF, чата, плана и удаления.
- MCP без доверенной области видит только подготовленный публичный пример.
- Перезапуск приложения с той же cookie, оригинальные байты и удаление.
- HttpOnly/SameSite, Secure на HTTPS, private/no-store и отказ чужому Origin.

На первом общем прогоне были 90 passed / 3 failed: старый контракт публичного
источника получил лишние поля; multipart-ошибка Starlette обходила единый JSON;
тест рестарта смешивал cookie-типы httpx и httpx2. Сохранена прежняя форма
seed-источника, обработчик охватывает исключения Starlette, тест переносит
cookie через обычный словарь. Итоговый прогон выше выполнен после исправлений.

Дополнительно прошли node --check web/app.js и git diff --check.
Новые зависимости зафиксированы в pyproject.toml, uv.lock и hash-locked requirements.lock;
сопутствующие версии не обновлялись ради этой функции.

## Проверка запущенного сервера

На http://127.0.0.1:8000 выполнен реальный HTTP-сценарий вне TestClient:

1. Главная страница с upload-form, JS и CSS вернули 200.
2. Исходный русский PDF и тестовый двухстраничный PDF загружены одним комплектом — 201.
3. Поиск через HTTP/MCP нашёл ORION на странице 2; источник содержит #page=2,
   оригинал совпадает с загруженными байтами.
4. Другая HTTP-сессия получила 404 на задание и оригинал.
5. Процесс сервера полностью остановлен и запущен снова; с прежней cookie
   задание доступно, checksum обоих файлов совпадает.
6. Созданное проверкой задание удалено; ссылки на него и исходники дают 404.

Проверочные записи удалены, пользовательские загрузки не затрагивались.
Сервер оставлен запущенным. Значения cookie и секретов в отчёт не включаются.

## Проверка интерфейса

Синтаксис JavaScript и соответствие DOM ID проверены. Через нативный Chrome
выбран и загружен PDF: UI показал успешное сохранение, три страницы,
список фрагментов, ссылки на PDF и ожидание следующего AI-этапа.
Поиск MCP завершился тремя фрагментами со страницами 1–2.
Подготовленный чат/план при выборе новой загрузки скрываются.
Открылась HTML-выдержка со страницы 2 и исходный PDF: браузерный просмотрщик
показал Page number = 2 из 3. Созданное для браузера задание затем удалено.

На реальном русском PDF замечены лишние переносы между словами. Исправлена
нормализация пробелов внутри страницы; regression проверяет читаемые фразы и
сохранение трёх страниц. После исправления исходный PDF даёт 2873 символа.
Полный визуальный прогон мобильной раскладки пока не заявляется.

LLM не вызывалась, API-ключ оставлен пустым. Эти результаты не являются
live Eval модели, проверкой Docker-образа или публичного хостинга.

## Основания реализации

- [pypdf: Extract Text](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)
  — извлечение текстового слоя и ограничение размера потоков.
- [Starlette: Requests](https://www.starlette.io/requests/)
  — multipart и ограничения формы; фактический размер запроса дополнительно
  ограничен нашим middleware.
- [MCP SDK: transports](https://py.sdk.modelcontextprotocol.io/client/transports/)
  — stdio и lifecycle соединения; версия SDK сохранена 2.3.0.
