# StudyNavigator

Учебный веб-ассистент: превращает материалы задания в проверяемые требования,
план подготовки и диалог с источниками.

**Сервис:** [открыть StudyNavigator](https://studynavigator.136-234-76-207.sslip.io/).
**Код:** [wVks/intelligent_system](https://github.com/wVks/intelligent_system).

MVP развёрнут на VPS. Работают загрузка PDF, подтверждение карточки, расчёт плана
и чат с настоящими LLM и собственным MCP-сервером. Полная мобильная/клавиатурная
приёмка и измеренная репетиция защиты ещё не завершены; качество ≥95% не доказано.

Новые материалы выступления находятся **только локально** в `presentation/`:
`index.html`, `plan.md`, `speech.md`. По указанию пользователя они
исключены из Git и Docker-сборки. Ранее опубликованный `web/defense.html`
остаётся историческим вариантом и не является новой финальной презентацией.

## 1. Название проекта и описание задачи

**StudyNavigator** помогает студенту понять, что нужно выполнить и сдать,
по каким критериям проверят работу и как распределить доступное время.

Основание задачи — [исходный учебный PDF](Личный%20проект.pdf), страницы 1–3.
Он требует интеллектуальную систему с подключённой LLM, собственным MCP,
интерфейсом, хостингом, Eval, README и интерактивной HTML-защитой до 10 минут.
Пользовательская загрузка PDF — выбранный сценарий нашего MVP, а не отдельное
требование преподавателя. Дата сдачи и согласование темы в исходнике не указаны.

## 2. Пользователь и сценарий использования

Пользователь — студент, начинающий работу над конкретным учебным заданием.

1. Загружает 1–3 текстовых PDF одного задания.
2. Открывает материалы и запускает AI-разбор либо заполняет карточку вручную.
3. Проверяет цель, результат сдачи, требования, критерии и срок; исправляет
   сведения и подтверждает карточку. Правки отмечаются как ввод пользователя.
4. Проверяет оценочные минуты, задаёт дни и доступное время, получает план.
   Выполненные задачи исключаются; при нехватке времени показан дефицит.
5. Уточняет задание в чате. Ответ ссылается на выдержку и страницу оригинального PDF.

Материалы, карточка и источники сохраняются на сервере. История чата и текущие
отметки выполнения живут в интерфейсе и не восстанавливаются после перезагрузки.
Если дата отсутствует, она остаётся неизвестной; план может быть относительным.

## 3. Границы MVP и критерии готовности

| Область | Реализовано |
|---|---|
| Материалы | Текстовые PDF, постраничное извлечение, SQLite/FTS5, поиск, просмотр и удаление |
| Карточка | AI-разбор, ручное заполнение без модели, подтверждение, происхождение сведений |
| План | Задачи конкретного задания, правка минут, завершённость, расписание и дефицит |
| Ассистент | Чат по выбранному заданию, источники, неизвестные данные и понятные ошибки |
| Интерфейс | Этапы работы, защита несохранённых правок, большой чат, план под ним во всю ширину |
| Текст | Безопасные абзацы и списки в источниках/сообщениях, открытие страницы PDF |
| Хранение | Постоянные файлы и БД, изоляция анонимных браузерных сессий |
| Размещение | Один VPS, Docker Compose, Caddy HTTPS, автоперезапуск и резервное копирование |

Ограничения загрузки: **1–3 PDF, до 10 MiB суммарно, до 100 страниц и
16 000 извлечённых символов**. Нужен текстовый слой: OCR и сканы не поддерживаются.
Повреждённые, защищённые и неподходящие файлы получают явную ошибку.

В MVP нет аккаунтов/ролей, восстановления анонимной сессии, интеграции с LMS,
уведомлений, календарей, DOCX, векторной БД, обучения модели и микросервисов.
Cookie разделяет доступ к материалам; это не полноценная система авторизации.
При утрате cookie прежнее приватное задание из другого браузера не откроется.

Критерии: работающая публичная ссылка, настоящие LLM/MCP, подтверждение ответа
источником, корректный план и сохранность данных после рестарта. Эти свойства
проверены в ограниченных сценариях; непрерывная стабильность, полная браузерная
приёмка и результат защиты не следуют автоматически из наличия тестов.
Публичность репозитория для пользователя без доступа отдельно не подтверждена.

## 4. Архитектурная схема системы

~~~mermaid
flowchart TD
  U[Браузер: PDF, карточка, чат, план] --> API[FastAPI backend]
  API --> F[Alice AI LLM Flash: разбор PDF]
  API --> C[Собственный MCP-клиент]
  C -->|stdio| S[Собственный MCP-сервер]
  S --> D[SQLite / FTS5 / файлы PDF]
  API --> P[YandexGPT Pro 5.1: ответ]
  API --> T[Python: минуты и расписание]
  API --> B[Общий сохраняемый журнал расходов API]
~~~

Стек: Python 3.12, FastAPI, Pydantic, SQLite/FTS5, pypdf и обычные HTML/CSS/JS.
Зависимости закреплены в `uv.lock` и `requirements.lock`.
Извлечённые материалы индексируются при загрузке. Файлы, карточки и денежный
журнал находятся в постоянном `/app/var`; ключ модели — в серверном env-файле
вне исходников. Frontend не получает API-ключ.

## 5. Схема MCP-интеграции

Клиент — `studynavigator/mcp_gateway.py`, сервер —
`studynavigator/mcp_server.py`. Используется настоящий MCP по stdio,
а не имитация HTTP-ручки или только подключение чужого готового сервера.

| Инструмент | Назначение |
|---|---|
| `list_assignments` | Список доступных заданий |
| `get_assignment` | Карточка, факты, требования и источники выбранного задания |
| `search_materials` | Поиск фрагментов, в том числе с ограничением по заданию |

Инструменты только читают данные. Область сессии задаёт приложение; модель
не выбирает чужой workspace. Неверные аргументы, неизвестные инструменты,
ошибки, timeout и предел вызовов проверяются кодом.

Для загруженного задания Yandex с пустым реестром typed facts **приложение**
выполняет `get_assignment` и `search_materials`, затем передаёт данные
модели. В трассе это отмечено `initiator=application`. Для подготовленного
примера работает ограниченный цикл выбора инструментов моделью.
Оба пути используют собственный MCP, но инициатор вызовов различается.

## 6. Описание AI-логики

На сервере явно выбраны фиксированные роли:

| Роль | Модель | Предел ответа |
|---|---|---|
| Разбор PDF в карточку | Alice AI LLM Flash | 2200 токенов |
| Объяснение по материалам | YandexGPT Pro 5.1 | 1000 токенов |

Необязательный `LLM_ANALYSIS_MODEL` переопределяет только анализ.
Если он пуст, обе роли используют `LLM_MODEL`; автоматического переключения нет.

RAG устроен как поиск FTS5 → найденные фрагменты через MCP → ответ модели.
Embedding-модель и векторная БД здесь не нужны: MVP использует текстовый поиск.
Для uploaded-пути модель получает компактный JSON-контекст и возвращает
структурированный ответ без tools. При ошибке формата допустим один ограниченный
повтор без tools, до 250 токенов, в том же timeout и денежном бюджете.
Подготовленный пример сохраняет tool loop, максимум 6 вызовов.

Код проверяет схемы, доступность источников, typed facts и известные даты.
Неизвестный срок остаётся `null`; минуты являются оценкой или вводом
пользователя, а не требованием преподавателя. Суммы времени и расписание считает
Python, а не LLM. Документы и ответы инструментов — данные, не инструкции агенту.

Live-ошибка не заменяется демонстрационным ответом. Без ключа доступен явно
обозначенный offline-режим. Свободный текст модели всё равно может содержать
ошибки: наличие валидного source ID не заменяет содержательную проверку.

## 7. Инструкция по запуску и развёртыванию

### Локальный запуск

Нужны Python 3.12 и `uv`. Из корня проекта:

~~~sh
uv sync --locked --extra dev
.venv/bin/python -m studynavigator
~~~

Открыть [localhost:8000](http://127.0.0.1:8000/).
Это offline-демо с настоящим MCP и детерминированными ответами, без оплаты API.
База и каталог загрузок создаются в `var/`; для остановки нажмите Control+C
в терминале запуска.

Для live создайте собственный `.env` по `.env.example`, заполните
`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`,
при необходимости `LLM_ANALYSIS_MODEL`, и выберите `STUDYNAV_MODE=live`.
URI Яндекса должен содержать каталог, доступный ключу. Запуск:

~~~sh
uv run --locked --extra dev --env-file .env python -m studynavigator
~~~

Обычный `python -m studynavigator` сам файл `.env` не читает.
Каждый разработчик создаёт свой env; ключи не коммитятся. Изменение настроек
требует перезапуска. Default приложения: 1000/3000 токенов и timeout 20/45 с;
на VPS явно настроены 1000/2200 и timeout провайдера/запроса 60/90 с.

### Итоговый бюджет

По разрешению пользователя совокупный потолок учтённых расходов API — **500 ₽**,
с учётом уже потраченного. Ранний локальный пилот хранится отдельно:
**23,0777 ₽**, 13 генераций. Поэтому серверный накопительный потолок выставлен
в **476,9223 ₽ = 500 − 23,0777**. Уже записанные серверные попытки включены в него;
история не обнуляется, дополнительные фиктивные вызовы не создаются.

`STUDYNAV_LIVE_BUDGET_RUB=476.9223` и
`STUDYNAV_LIVE_BUDGET_PATH=/app/var/live-stage6-budget.json`.
Это общий предел чата и анализа, не ежедневная квота. Сервер допускает явно
настроенный максимум 500 ₽; без переменной денежный guard выключен.

Перед каждой платной HTTP-попыткой резервируется консервативная сумма.
Неизвестный расход сохраняется как резерв; при нехватке запрос не отправляется.
Смена лимита требует согласованного обновления env и ledger при остановленном app
с резервной копией, аудитом разрешения и сохранением всех расходов.
Нельзя удалять журнал или очищать `usage_exceeded_reservation` без диагностики.

Локальный Eval CLI сохраняет собственный максимум 25 ₽. Новые платные проверки
следует вести через общий серверный журнал: отдельные локальные расходы
потребуют пересчёта исторического вычета. Это контроль приложения по учтённым
журналам, а не жёсткий лимит всего аккаунта Billing Яндекса.

### Размещение и сохранность

Сервис размещён на VPS Ubuntu 26.04.1, Docker/Compose и Caddy.
Рабочая директория — `/opt/studynavigator/app`, серверный env —
`/opt/studynavigator/server.env`, права 0600, вне сборки и репозитория.

~~~sh
cd /opt/studynavigator/app
docker compose --env-file ../server.env config --quiet
docker compose --env-file ../server.env build app
docker compose --env-file ../server.env up -d --wait
curl --fail https://studynavigator.136-234-76-207.sslip.io/health
~~~

Backend работает от UID 10001 с одним worker, read-only корнем и постоянным томом
`studynavigator_app_data`. Порт 8000 наружу не опубликован; HTTPS завершает
Caddy. Настроены healthcheck, ротация логов и `unless-stopped`.
Не используйте `down -v` для обновления; `docker compose config` запускайте
с `--quiet`, чтобы не вывести секреты. Домен технический и зависит от IP VPS.

Backup при остановленном app восстановлен в отдельном offline-томе без сети:
4 задания/PDF и журнал расходов сохранились. Реальный reboot VPS вернул HTTPS
за 21,2 с. Это историческая проверка до позднейших UI-правок; после них отдельно
проверена сохранность шести заданий. При восстановлении старого backup сохраните
актуальный денежный журнал, чтобы не открыть уже потраченный лимит повторно.
Подробности — [deploy/README.md](deploy/README.md).

**GitHub не является runtime-зависимостью.** Исходники и зависимости уже находятся
на VPS и в Docker-образе. Удаление пользователя из collaborators само по себе
не остановит контейнер: пока сохраняются VPS, образ/данные, DNS и доступ к API,
сайт продолжит работать. Пропадёт возможность обновлять закрытый репозиторий;
повторное клонирование/выкладка могут потребовать возвращения доступа.
Если отдельно отзывают доступ к хостингу или API-ключу, это уже влияет на сервис.

## 8. Результаты Eval и разбор ошибок

| Проверка | Фактический результат и область |
|---|---|
| Python | 317/317 после изменения бюджетного потолка, 54,25 с |
| JS/HTML | 35 проверок: состояния UI, списки/XSS, источник/PDF, порядок блоков и DOM-контракты |
| Offline Eval | 30/30 в предыдущем сохранённом прогоне; это не живой LLM |
| Бесплатный HTTPS smoke | 27/27 после обновления источников и вёрстки |
| Сохранность | 6 прежних заданий, карточки, источники и хеши PDF после обновления |
| Свежий live HTTP | 8/8 случаев на новых загрузках, без replay БД |
| Содержательная проверка live | 13/13 заранее заданных рубрик, один малый диагностический набор |

Свежий live-прогон использовал фиксированные Pro/Flash, настоящие MCP-вызовы,
новые PDF и реальные AI-разборы. Его пять генераций стоили 7,4579 ₽.
Остальные случаи проверяли подтверждение, арифметику плана и приватность.
Это **один прогон**, не доказательство качества ≥95% или стабильности на любых PDF.

Ошибки не удалялись из истории:

| Ошибка | Решение или ограничение |
|---|---|
| Flash выбирала неизвестный инструмент в чате | Фиксированные роли: Pro для чата, Flash для анализа |
| Модель придумывала typed fact | Явный реестр фактов и строгая проверка; uploaded-контекст содержит `facts=[]` |
| Некорректный финальный JSON | Контролируемый MCP retrieval и структурированный ответ, один ограниченный repair |
| Нехватка резерва API | Отказ до отправки; сохранённая история и согласованное увеличение лимита |
| Вымышленный срок | Канонические данные и явная неизвестная дата |
| Слитный PDF-текст и зависший статус UI | Безопасные абзацы/списки и очистка состояния ошибки |

Ранние 5/8, 7/8 и целевые повторы на разных версиях не выдаются за единый
финальный набор. Анализ источника сокращает промежуточные уровни рубрики;
предложенный список задач также может требовать правки пользователем.

В Chrome ранее частично проверены загрузка, источник/PDF и клавиатурные переходы.
Последние макеты, мобильные ширины и полная клавиатурная приёмка не проверены
визуально: после отказа CUA пользователь выбрал продолжение без браузера.
Новая локальная презентация проверяется отдельно; план 8:30 не является
измеренной репетицией. Согласование темы и оценку подтверждает преподаватель.

Основные бесплатные команды:

~~~sh
.venv/bin/python -m pytest tests/app -q
node --test tests/web/*.cjs
.venv/bin/python tools/run_app_eval.py --output var/eval-offline.json
.venv/bin/python tools/check_hosted.py https://studynavigator.136-234-76-207.sslip.io
~~~

Платные runners требуют явного `--execute`; без него выводится только план.
Не запускайте их ради обычной проверки UI. Полные отчёты с cookie находятся
в игнорируемом `var/`; опубликованы только обезличенные результаты.
