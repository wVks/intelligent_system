# Материалы и проверка сдачи StudyNavigator

Источник требований: «Личный проект.pdf» в корне проекта, страницы 1–3.
Это учебная рубрика, а не свидетельство готовности текущей реализации.

## Требуемый результат

- Работающая интеллектуальная система: подключённая LLM, реализованный
  MCP-сервер со стабильной интеграцией и WEB/TG/MAX/etc-интерфейс.
- Сервис развёрнут на хостинге и доступен по ссылке.
- Публичный репозиторий с единым основным README.md и интерактивной
  HTML-презентацией. Другие исходники и результаты проверок хранить можно.
- Проведён Eval; его результаты и разбор ошибок оформлены в README.
- Для LMS нужны две ссылки: репозиторий с README и презентацией; сервис.
- Защита синхронная: интерактивная HTML-презентация до 10 минут,
  демонстрация работающего сервиса и ответы преподавателю и группе.

## Девять разделов README

1. **Название проекта и описание задачи.** Какую проблему решает система.
2. **Пользователь и сценарий использования.** Кто обращается и какой результат получает.
3. **Границы MVP.** Реализованный объём, критерии готовности и ограничения.
4. **Архитектурная схема системы.** Компоненты и реальный поток данных.
5. **Схема MCP-интеграции.** Клиент, сервер, транспорт, инструменты и их роли.
6. **Описание AI-логики (модель или агент).** Конфигурация модели, выбор
   инструментов, источники, поведение без данных и ограничения цикла.
7. **Инструкция по запуску и развёртыванию.** Зависимости, настройки без
   секретов, подготовка данных, команды, URL и проверка после запуска.
8. **Результаты Eval и разбор ошибок.** Версия набора, команда, конфигурация,
   фактические результаты, примеры ошибок и известные ограничения.
9. **Список использованных источников.** Учебные материалы и технические
   источники, действительно использованные в реализации.

Структуру можно адаптировать к репозиторию, сохранив все девять пунктов.
Ссылки на файлы результатов дополняют раздел Eval, а не подменяют его.

## Точная рубрика PDF: пять критериев по 10 баллов

| Критерий | 0 баллов | 5 баллов | 10 баллов |
|---|---|---|---|
| Задача и границы | Задача не сформулирована или не соответствует критериям | Задача сформулирована, определены пользователь и сценарий использования | Дополнительно определены границы MVP, сформулированы критерии готовности, задача согласована с преподавателями |
| MCP-интеграция | MCP отсутствует | MCP-сервер реализован, но интеграция частичная или нестабильная | MCP-сервер реализован, интеграция работает стабильно, схема MCP описана в README |
| Сервис и хостинг | Сервис не развёрнут, работает только локально | Сервис развёрнут, но работает нестабильно или недоступен по ссылке | Сервис развёрнут на хостинге, доступен по ссылке, работает стабильно |
| Качество и воспроизводимость | Eval отсутствует, README не позволяет воспроизвести проект | Eval проведён, README содержит инструкцию по запуску, но есть пробелы | Eval проведён, разбор ошибок оформлен, README позволяет полностью воспроизвести проект |
| Демо и ответы | Демонстрация отсутствует или не работает | Демонстрация проведена, но есть проблемы с работоспособностью или ответами на вопросы | Демонстрация работает, ответы на вопросы полные и аргументированные |

Максимум — 50 баллов. Согласование темы с преподавателями подтверждается
отдельным фактом; не объявляй его состоявшимся по наличию описания проекта.
Итоговые баллы выставляет преподаватель.

## Сценарий интерактивной HTML-презентации

Предлагаемый порядок занимает до 9 минут и оставляет минуту запаса;
это рекомендация, в PDF задан только предел 10 минут.

| Время | Содержание |
|---|---|
| 0:00–1:00 | Проблема, пользователь, один конкретный сценарий |
| 1:00–2:00 | Границы MVP и критерии готовности |
| 2:00–3:30 | Архитектура, MCP-инструменты и путь запроса |
| 3:30–6:30 | Живое демо: требования задания, план с известными ограничениями, вопрос без данных |
| 6:30–8:00 | Реальные результаты Eval, одна ошибка и её разбор |
| 8:00–9:00 | Ограничения, воспроизводимость, ссылки на сервис и репозиторий |

Реализуй содержательную интерактивность: переход между разделами/слайдами,
раскрытие примера вызова MCP или результата проверки, открытие сервиса.
Проверь клавиатурную навигацию и читаемость на экране защиты. Скриншоты
и запись могут дополнять демонстрацию, но не доказывают доступность сервиса.

## Проверки запуска и хостинга

Для каждого существенного пункта укажи статус и краткое доказательство:
команда и код выхода, проверенный URL, наблюдаемое поведение или путь
к результату. Не оставляй в отчёте фиктивные значения и успешные отметки.

| Проверка | Достаточное свидетельство |
|---|---|
| Чистый запуск | Следование README в отдельной среде с зафиксированными зависимостями |
| Полная локальная цепочка | Фактический LLM-вызов и MCP-обмен с ответом по источнику |
| Офлайн проверки | Явно обозначенный mock и список проверенных им компонентов |
| Публичная доступность | Открытая ссылка и выполненный через неё пользовательский сценарий |
| Состояние после рестарта | Повторная проверка базы и основного сценария после перезапуска |
| Eval | Сохранённый результат конкретного запуска с ошибками и конфигурацией |
| HTML-презентация | Открытие файла, проверка управления и измеренный либо непроверенный хронометраж |

Если сети, ключа или аккаунта нет, пометь зависимую проверку «не проверено»
и назови причину. Отсутствующий сервис — «не выполнено». Не превращай
mock-результат в live-результат. Провайдер модели и хостинг выбираются
по реальной доступности; сам PDF конкретных поставщиков не требует.
